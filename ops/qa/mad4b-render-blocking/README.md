### 2026-10-31: Tour Rate departure data is explicit, not seeded
The observed 8-day tour ID 60623 has an empty `tour_origin_location_term`; its four Rates #60840/60850/60860/60870 contained identical unconfirmed data: Friday term 234, Afternoon term 236, and legacy Africa/continent term 2306. JetEngine Rate CPT #328 query-backed selects had no neutral choice. With exact site+rate+value preflight, a targeted WP-CLI operation backed up all twelve original values under `mad4b_unconfirmed_rate_schedule_60623_backup_20261031` and cleared only these three unconfirmed meta keys on these four Rates. No other Rate or Production data was modified.

Staging source MU 313 implements `show_rate_departure_details` as an explicit, False-by-default JetEngine CPT radio from existing Glossary #321 `True OR False(Default)`. It extends the CPT fields so queried weekday/time and the deprecated legacy origin selector have an empty default plus `Not specified` placeholder; an admin-only Select enhancement inserts a first empty choice without erasing existing persisted selections. This is a non-guessing authoring model, not a default term ID. An exact metadata backup `mad4b_rate_departure_schema_backup_20261031_v1` exists. The migration is idempotent and is invoked via `wp mad4b rate-departure migrate --confirm='STAGING RATE DEPARTURE SCHEMA'` with site UUID binding/readback.

Both native compact Tour Rate headings (TK dynamic source) and the JetEngine Elementor listing field widgets use the same opt-in Boolean. When False, no unconfirmed weekday, time or origin text is displayed. When True, the origin is resolved **only** from the related Tour's `tour_origin_location_term` or `tour_origin_address` term ID, rejecting continent and country terms; a missing Tour origin is omitted, never fabricated. Existing WPML translation of destination terms is respected. Both Elementor template 46193 and its translation 46557 share the guarded widget identities. The six guarded widgets publish independent data-mad4b-departure-optin attributes for read-only inspection. Chrome confirmed two price titles without Friday/Africa/Afternoon, hidden schedule widgets, zero overflow. Isolated PHP tests exercise False, True, source Tour Cairo origin, stale Africa rejection, and missing origin. A browser DOM test confirmed `Not specified` becomes selected for empty stored data while an intentional saved Afternoon choice is preserved.

The mobile Tour Contents -> About H2 gap was 58px because Elementor widget #c16d4db adds a 58.368px top margin to its inner widget-container. The CSS patch scopes a 16px margin to <=767px while preserving the TOC's 12px top spacing. English and Arabic Chromium both measured a 16px bottom gap; tablet and desktop margins remain unchanged.
