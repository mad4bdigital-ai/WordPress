# Default AI executor: ChatGPT MCP Client (source-governed)

**Scope:** MAD4B Content Hub on `tours.dev.mad4b.com`, Staging. This document does not grant Full Enforcement or Production mutation.

## Existing immutable default

The original `MAD4B_Hub_Execution_Router::DEFAULT_MODE` is `mcp_client`. This is the ChatGPT MCP Client handoff lane, not a separate background model running on the VPS. The visible `chatgpt_client` mode is an alternate selector label, **not** a reason to rewrite durable Queue executor IDs or to silently switch existing jobs. Missing or invalid per-Job selections fall back to `mcp_client`.

The router exposes the authenticated ChatGPT client only if the original OAuth resource bridge verifies the exact bearer client identity (`https://chatgpt.com/oauth/client.json`). WP-CLI fallback requires an authenticated WordPress user and does not impersonate OAuth. An MCP handoff creates a plan and may enter `WAITING_EXECUTOR`; it is not proof that ChatGPT ran a model or completed a stage.

## Before AI-lane certification

1. Keep `mcp_client` as the system default. `background_ai_enabled` remains false unless a governed, separately authorized and tested opt-in has been made. Per-job `background_ai` selection requires the explicit setting **and** an actually registered worker; no silent fallback.
2. Confirm live runtime `MAD4B_Hub_Execution_Router::status()` from an authorized original WordPress principal. Inspect current option `mad4b_hub_execution_router_v1`, count any explicit per-Job overrides and reconcile them separately. Source defaults alone do not prove live settings or eliminate existing overrides.
3. Keep VPS guard/preflight tasks separate from the model-executing MCP client. `vps_runner` for non-model guard tasks does not mean AI output was generated by the server.
4. Before extending Full Enforcement beyond existing certified read-only operations, require original ContentJob revision and stage, signed/persisted client/worker grants, independent source and artifact receipt, model invocation proof, bounds on usage, duplicate/replay tests, compensation, and separate publishing review authority.
5. Do not mutate the original 20 nonterminal legacy tasks just to satisfy a new semantic plan; retain their locked allowlist and reconcile identity, original event, or stage using provider readbacks.

## Release contract

`tools/test_mad4b_hub_ai_client_default.py` is imported by the existing Content Hub release-gate suite, so the exact-head GitHub CI must reject changes that accidentally make background AI the default, claim a backend model call, bypass the authenticated MCP identity or conflate a guard task with model execution.

**Current verified operational scope from prior acceptance:** `certified_only` for `workflow_inspect`, `content_job_read` and `runtime_resolve`. Full `enforce` remains NO-GO pending source-specific certification of AI, pricing, inventory, publishing and provider effects. No Production mutation authorized.
