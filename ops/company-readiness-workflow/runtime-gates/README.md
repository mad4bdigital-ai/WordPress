# MAD4B — Mandatory Governed Runtime Dependency Gates

## Why

A cloned WordPress database schema **does not** prove that the cloned tenant has the PHP providers, commercial rate engines, Elementor display conditions, media mappings or company login presentation required to operate its templates. A published JetEngine/Elementor template does not prove a dynamic tag will resolve.

## Mandatory execution contract

The `company-readiness-workflow` executes `company-governed-runtime-gates.py` against the target tenant on **every** readiness evaluation. It reads the actual enabled plugin slugs, WordPress CPT registration, runtime functions, Elementor registered dynamic tags referenced by published and draft templates, old media/URL references, active Elementor Theme Builder conditions, current Company Options Registry and the rendered HTTPS WordPress login. The exact site/domain/company UUID and database identity must match the tenant configuration.

A failed runtime probe **fails closed** rather than reusing a stale report. The central readiness report records each result and automatically invokes the on-difference compatibility resolver, which queues specific fixes without changing the tenant.

The consolidated lifecycle `wayfa-design-lifecycle.py --mode auto` now checks these gates **before any auto-apply**. While any mandatory gate fails, it executes read-only plans and returns `BLOCKED_MANDATORY_RUNTIME`; it cannot incorrectly report `SCHEMA_AUTO_COMPLETED` and cannot silently publish new templates.

The eventual target is a company-parameterized contract, not copying Woo Vacation's entire plugins/MU directory. The first company contract is `company-governed-runtime-contract-v1.json`, scoped to `wayfatours`. Extend via a central approved company configuration before other tenants. Optional blank brand text/media fields are allowed after onboarding; missing operational providers are not.

## Nine required checks

1. `runtime_code_bootstrap` — WordPress providers, registered Tours/Properties/Transport CPTs, WooCommerce, WPML.
2. `commercial_pricing_and_rate_engines` — expected native pricing/rate plugin dependencies and actual quote/currency/rate functions.
3. `commercial_transport_rate_engine` — native transport bridge and transport rate resolution.
4. `published_template_runtime_dependencies` — **zero unsupported dynamic tag instances in live published templates**, not fake empty tag stubs.
5. `company_media_asset_mappings` — no old source references in published design; draft unconfigured media is tracked separately.
6. `company_page_url_and_wpml_links` — source paths and original language links need tenant-native mappings or explicit blank deferrals.
7. `elementor_theme_builder_conditions` — live company Header/Single/Archive display rules, no blind source condition inheritance.
8. `company_login_code_and_identity` — working login presentation, company name, valid HTTPS and no source logo/domain.
9. `company_options_runtime_registry` — company-backed JetEngine Options definitions available; company values remain tenant-owned.

The central site should not enable Content Hub distribution or Woo checkout based on schema/template publication alone. Source-specific REST endpoints are excluded from the portable blueprint: as of this run the source owns 3 `mad4b-hub-*` REST configurations (#390-392) for research, article and tour; the tenant keeps the 307 portable structural models. Each source-specific REST endpoint must remain owned by the source and not be copied to Wayfatours.

## Source login mismatch and corrective action

The source login design is generated by the `custom-css-js` plugin from source WordPress record **25477**, `Stylish Login CSS`, not by Astra or Elementor. It was missing on the tenant and included a hardcoded **All Royal Egypt** logo URL; copying it verbatim would violate brand isolation.

Tenant MU `248-mad4b-company-login-presentation.php` reproduces the visual layout (radial gradient background, rounded white 380px login card, mobile adjustments) without old hardcoded artwork. The header uses the **Wayfatours** site label and, if supplied by the owner, only the tenant's validated local JetEngine brand logo. The login endpoint was probed live at HTTP 200 with valid TLS, matching the expected CSS marker and no old source brand/domain.

Commercial engine source plugins such as `mad4b-pricing-registry`, `commerce-composition`, `cpt-woo-integration`, `woocommerce-travel-bridge` and `mad4b-jetengine-hub-addon` were not enabled on the target at verification. This is **not** authorization to copy the entire source plugin tree; compatible signed-off company-neutral provider modules require PHP dependency and data isolation tests, with native quote/rate readback and appropriate company scope. Avoid invented booking prices and fake successful stubs.

Workflow readback: central status `BLOCKED_FOR_COMMERCIAL_DISTRIBUTION`, runtime completion `false`, resolver triggered with distinct runtime blockers. The login and gate implementation were written live to Wayfatours/VPS; GitHub contains code, tests, and contract in Draft PR #655, not yet a merged deployment.

## Reproduce (read only on tenant)

```bash
python3 /opt/mad4b-company-provisioning/bin/company-governed-runtime-gates.py
python3 /opt/mad4b-company-provisioning/bin/company-readiness-workflow --refresh
python3 /opt/mad4b-company-provisioning/bin/wayfa-design-lifecycle.py --mode plan
# --mode auto now refuses production mutation when runtime is not ready
python3 /opt/mad4b-company-provisioning/bin/wayfa-design-lifecycle.py --mode auto
```

The workflow stores only aggregated diagnostic references and metadata on central Staging. It never copies tenant customer data, source author credentials or provider secrets and does not bypass native WordPress security rules.
