# MAD4B VPS original transport runtime — live mirror

Source snapshot from the running VPS. Runtime owner: /opt/mad4b-company-transport/.
These files mirror executable modules, not an independent Broker or
a new authority issuer. Keep the original 305 / 306 / 312 / 313 admission chain.

Deployment paths are relative to the runtime root. systemd/ files are the
current Dispatcher split configuration under /etc/systemd/system/. They are
not new timers and MUST NOT be activated merely by merging source.

The dynamic site resolver permits read-only observation of an exact Coolify
php-<project> container when Docker labels, the registered locator,
WordPress canonical origin, Site Profile UUID and environment agree.
A candidate remains observed_not_enrolled: observation never issues a grant.

Site registries, SSH credentials, options, signed receipts, host keys,
secrets and runtime state are deliberately NOT versioned here.
Enrollment is managed by the existing Original authority, not from Git.

Unit tests are located in the three original active runtime directories:
dynamic-site-binding-v1, registry-remote-v1 and broker-v1.
Promotion requires an exact diff, tests, atomic backup and readback.
Do not copy older Git builds over live WordPress or tenant sites.
