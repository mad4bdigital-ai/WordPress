# MAD4B Delayed Hero — Responsive LCP delivery v0.5.3

Reuses the original `MAD4B_Delayed_Hero_YT` Elementor container hook and settings, not a new widget. The `mad4b_perf_hero_responsive_lcp_v1` option must be explicitly `on` and `mad4b_perf_hero_responsive_languages_v1` lists the admitted WPML language codes. Default is fail-closed (`off`). A site-admin-selected explicit hero poster stays authoritative; only its own smaller derivative or an explicitly configured company compact poster is eligible. The existing fallback tour poster remains for sites without a company override.

`poster()`, the Elementor container render, and `preload()` all share a single responsive media policy. The browser's early inline resolver selects exactly one `<link rel=preload as=image fetchpriority=high>` using `matchMedia` (no UA/device-class split), while the Elementor wrapper uses `var(--mad4b-lcp-image)` with the identical CSS predicate. There is no extra image, video element or parallel Elementor template. On JS-disabled browsers, the responsive CSS still selects the correct image; the preload is skipped, not a different asset.

**Cache warning:** Elementor's `_elementor_element_cache` contains the old rendered wrapper and must be selectively invalidated for templates containing the authored hero when turning this on or changing the policy. Purge only affected public route generations using the installed MAD4B native cache service; do not purge Redis globally or bypass production company governance.

The HTTP HTML must be identical for all user agents of the *same language and route*. The preload must match the selected CSS background, never duplicate both wide and compact requests. Test relevant widths, DPR (especially 390px DPR 4 and 820px foldables), EN+ES WPML, desktop, disabled JS, search popup, calendar, and native video fallback. Run `ops/company-code-release-v1/tests/verify_hero_responsive_v053.js` in Playwright (set `NODE_PATH` to your available Playwright install) against each permitted site; it asserts one matching poster request, no overflow or page errors. The site identity is an explicit CLI argument, not hardcoded.

The direct VPS rollout is not a signed Original313 receipt. Live browser smoke and external Lighthouse should be repeated: no single Lighthouse score certifies stability. If `Critical CSS` stops reporting ready, fail closed/restore the preimage and diagnose the CSS lifecycle before expanding rollout.
