# MAD4B Nile Tour Facts and Content Hub Extras

This is a diagnostic, read-first MAD4B Skill. It provides NO authority to publish a Draft, invent supplier entitlements, quote an unapproved rate, bypass transport service policy, or overwrite Elementor templates in bulk.

## Native Tour Facts

1. Inspect `MAD4B_Nile_Tour_Facts_Minimum_V1::audit($tour)` and the native JetEngine `Tour Terms Section` for the company's language/template. Minimum fact keys: `destinations`, `duration`, `guide_languages`, `tour_types`, `tour_category`, `boards`, `group_size`; inspect Cruise Runs separately.
2. `Destinations`: country and actual route cities are derived only from the Tour's destinations and canonical Program Taxonomy itinerary, not from optional activities or arbitrary nearby locations. Preserve geographical parent chains, and do not invent cities from incomplete descriptions.
3. `duration-options`: match 3/4/7-night Program itinerary to native taxonomy terms using site-local slugs, not fixed IDs. Archive terms require native term relations. For Cruise Tour, the original Elementor Duration card is intentionally hidden in favor of `Run`; do not override the theme merely to make its count match a non-cruise template.
4. `tour-types`: native Tour explicit children first; complementary Property-derived vessel family and star/amenities appear from the `MAD4B_Nile_Intelligent_Inheritance_V1` resolver. An inherited suggestion is NOT automatically indexed in native Tour Type filters.
5. `board-type` is owned exclusively by the selected published Cruise Property: it is inherited dynamically into the native Elementor Board card via `jet-engine/listings/dynamic-terms/items` plus custom `mad4b-nile-property-has-boards` JetEngine visibility condition. Do not duplicate Board terms on Tours, and do not require Tour term materialization for publication. A missing Board source raises a Property-level Ready to Publish gap (`minimum_tour_fact_boards_unverified`) referencing the Property ID; fix the Property taxonomy and allow targeted cache invalidation to propagate. Available vessel board labels do not by themselves approve Rate-level meal inclusions or checkout.
6. `guide-languages` and `tour_categories`: commercial promises need Tour/operator/Rate source evidence. Do not set English, Group Tour, meal inclusions or special guide entitlements based only on passenger count, dining amenities or unrelated Extra Trips. Return a required editorial/Content Job review issue instead.
7. Inspect Run listing text fields separately from Program term fields: `program` is a term ID that needs `jet_get_term_name`; `day`, `origin`, `time` are plain repeater strings and must not use a taxonomy-name filter. Preserve original Elementor CSS, cards, and WPML locale templates.

## Content Hub / Extra Trips

1. Differentiate Content Hub source availability, the parent Tour's `tour_optional_extras` relationships, child activity `post_status` and `tour_public_status`, JetEngine Query Builder provider, Elementor template/container display, and actual checkout eligibility. Any one missing link can cause a hidden Extra Trips section.
2. Resolve the `current_tour_extras` query from the nested Elementor Listing Grid and compare it to parent `query-has-items`. Do not mistake the vehicle Query for activity presence. Fix provider mismatches through independent expected SHA, private preimage, minimal CAS and readback, including WPML-aligned copies.
3. Respect `extra_options_display_mode`: the authenticated front-end Draft preview and published route display exactly one of native carousel vs list; the actual Elementor editor may inspect both. Never add substitute non-native cards to mask a missing provider.
4. “Showing 0 Result” can be a stale count widget when cards appear: check the selected mode and independent JetEngine query results, do not zero out valid published activities. Displayed source prices are NOT approved quotes for Draft Tours.
5. Vehicles, trains and air: enforce exact transport `trans_mode`, selected IDs, service availability policy and verified Tour context. A Draft preview may diagnose blocked transport rows but cannot authorize guest service-channel access, WooCommerce checkout or Stripe payment.
6. Frontend testing must distinguish logged-in authorised Preview from guest. Record actual cards, DOM/interaction, WPML language, CSS, query counts, missing facts and services, and independent readback. Do not claim browser click parity from WP-CLI render alone.

Return: `tour_id`, `status`, `minimum_facts`, `native_term_links`, `verified_inheritance`, `missing_supplier_claims`, `content_hub_extra_ids`, `public_eligibility`, `query_binding`, `display_mode`, `transport_policy`, `readback`, `rollback`, `ready_to_publish`.

## Optional Activities & Transport — published but nonpublic preview

- The saved WordPress post `publish` state is different from the legacy publication flags. Activities (Tour CPT) use **`tour_public_status`**; Transportation CPT uses the actual misspelled JetEngine field **`trans_is_puplic`**. The precise value `0` excludes a component from public discovery and commerce, even when the linked post is Published. Do not silently rename the field, mark it `1`, or enable checkout just to render an editor preview.
- The parent Tour's JetEngine links are `tour_optional_extras`, `vehicles_transport_services`, `train_transport_services`, and `air_transport_services`. The section enablement fields must be on. Extra trip posts need an allowed `tour_mode` (`activity` or `extra_trip`); each transport must match the requested native transportation taxonomy and `trans_mode` (vehicle 568, train 578, air 594) as verified by `Shared_Product_Presentation_Transport_Context_v1::candidate`. Never present a car as air transport because the same ID was selected in the air selector.
- Production/public presentation remains gated by the `service-activation` policy and published main Tour authority. For **authenticated Draft Cruise Tour editor preview** only, the compatibility policy `compat/mad4b-platform/097-service-channel-policy.php` permits read-only transportation display when the service is allowed for `tour_component`, the immutable main `wp_the_query` has a verified Draft Tour preview, the user can edit that tour, and the Tour has a valid enabled transport relation. This grants no standalone discovery, price, rate, booking, checkout, or guest visibility. Do not set the global service mode to standalone to solve editorial preview.
- Native Elementor optional-extras and transportation listing templates are Tour-dependent and must never reuse a snapshot cached for another Tour. The MU `mad4b-tour-private-optional-preview-cache.php` selectively bypasses their shared `_elementor_element_cache` **for authenticated Draft Tour previews only** and prevents writing private Tour-specific rendered content back to the shared Elementor cache. Public rendering, unrelated templates, WordPress asset caches, and `wp_options` stay untouched.
- The editor preview diagnostic distinguishes published private **unique items** from linked references. Do not count a reused vehicle in the air selector as a valid air candidate or as an additional unique item. For QA Tour #69715 the selected activities #60467/#60469, car #39707 and trains #54554/#54555 are `publish` with their respective private flag `0`; source-language renderer checks must show both activity cards plus one vehicle and two train cards. An incorrect air-to-car relation (#39707) was found and removed from the QA parent Tour using exact-row CAS, with `tour_air_transport_status=0` until a valid air transportation exists. Treat `transport_wrong_mode` as a blocking data-quality alert if the editor reintroduces it; do not display that car inside Air Transport.
- Test negative boundaries: logged-out guest in the same Draft preview must not gain transport presentation authority, Woo/quote must still deny nonpublic extras, and the parent remains Draft with no published Tour Rate. Do not claim that `is_puplic=0` makes the direct WordPress permalink access-controlled; a Published post may still have an accessible URL unless a separate route authorization policy restricts it.
- In an authorized QA test, compare raw SQL SHA256 of `_elementor_element_cache` on native templates before and after rendering. The cache must stay byte-identical, while native JetEngine extra and transportation cards render. Don't replace the original listing cards with fabricated HTML, clone already-linked posts by default, or mark unverified prices as bookable.

## Transport galleries — strict Elementor branch + per-vehicle media ownership

- The native JetEngine listing `40299` is one multi-branch Elementor listing. Keep its **three original branch containers** and **three original gallery widgets**; do not duplicate or render cross-mode sub-listings. Each branch's visibility must be a logical **AND** between `post-has-terms` for its root `transportation-types` taxonomy term and `trans_mode == that same root term ID`. These values come from the source taxonomy, not from a static list of allowed operation names. The source-backed, CAS-only migration `migrations/transport-gallery-branch-contract.php` preserves the exact tree and reversible SQL JSON preimage.
- For every branch, the native JetEngine gallery dynamic-field widget must read the **current transportation post's** `trans_gellery` meta directly (source `meta`) with `hide_if_empty=yes`, without inheriting `units__unit_gellery` from a Unit relation. An empty/wrong-mode gallery should hide rather than borrow other vehicle thumbnails. The value of `trans_mode` alone must not authorize a branch if that transportation post lacks the corresponding root taxonomy term; similarly a misassigned term must not override `trans_mode`.
- Gallery reuse among **the same transport mode** can be normal (e.g., two services using the same train equipment); do not assume duplication alone is a defect. An entire identical gallery reused between **different** modes is a data-quality risk. The dynamic `MAD4B_Transport_Gallery_Integrity_V1::audit($tour)` reads all valid Tour-linked transportation IDs, compares full gallery SHA by `trans_mode`, confirms native taxonomy alignment, and emits per-post `transport_gallery_reused_across_modes`, `transport_gallery_missing`, or recorded manual-review alerts.
