# MAD4B — Team Workload And Sla

This Skill is company-scoped, advisory and read-first. It does not add WordPress permissions, MCP abilities, payment powers, API secrets or arbitrary shell authority.

## Procedure

1. Resolve the exact company Board ID, allowed internal staff, company master role, and task ownership; never treat team links from another tenant as valid.
2. Read original Fluent Boards tasks and MAD4B Content Jobs/Readiness work queues; distinguish pending, in progress, blocked, overdue, retried and verified.
3. Group tasks by department and operational impact, including traveler inquiries, booking payments, content/SEO, translation coverage and release readiness.
4. Compute SLA risk from actual deadlines and status timestamps; report missing deadlines as unknown rather than invented late work.
5. Suggest assign/reassign/escalate using only approved staff members; the bounded Company Master Admin task-assignment API must confirm a successful native readback.
6. Preserve task audit history and notification preferences. No automatic reassignment or messaging during a read-only review.
7. Summarize team capacity, overdue critical work, owner, next action, and escalation condition.

## Result contract

Return the exact company/environment, selected native data sources, operation owner, evidence freshness, proposed action, authorization status, verification method and reversible rollback path. Unknowns remain explicit.
