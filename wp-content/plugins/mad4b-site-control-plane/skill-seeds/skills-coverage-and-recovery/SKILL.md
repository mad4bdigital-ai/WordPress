# MAD4B — Skills Coverage And Recovery

This Skill is company-scoped, advisory and read-first. It does not add WordPress permissions, MCP abilities, payment powers, API secrets or arbitrary shell authority.

## Procedure

1. Read `mad4b/skills-list`, `mad4b/skills-runtime-certification`, Site Profile readiness, provider discovery and current build identity for each exact company independently.
2. Distinguish seeded 21+ canonical workflows, provider-discovered skills and company-specific optional Marketplace/Cruise workflows. Compare logical IDs and enabled state, not raw totals.
3. Separate `catalog_read_ready`, `external_app_projection_ready` and `authoring_ready`; a Production editor-off policy must not hide a usable read catalog.
4. Where Skill is missing, inspect eligible provider, canonical managed digest and locally customized file first. Do not overwrite user-owned `SKILL.md` or activate unsupported plugins.
5. Identify App mapping by the enrolled Site Profile identity. Never copy an App ID, OAuth session or grant from a different company.
6. Build a bounded reconcile plan with read-only diff, exact target, source checksum, rollout mode, rollback and native registry readback.
7. Report READY / OPTIONAL / UNAVAILABLE / BLOCKED / STALE per logical ID and company. Only a separately authorized lifecycle may mutate runtime registration.

## Result contract

Return the exact company/environment, selected native data sources, operation owner, evidence freshness, proposed action, authorization status, verification method and reversible rollback path. Unknowns remain explicit.
