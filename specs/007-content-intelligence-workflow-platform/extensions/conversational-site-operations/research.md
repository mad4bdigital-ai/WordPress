# CSO01 — Evidence, decisions and unresolved compatibility questions

Grounded in existing WordPress repo: Unified Capability Gateway, Descriptor Registry, Site Capability Discovery, Semantic Content Field Contracts, governed Abilities, Mutation Manager and G6 Conversation Vault are reusable primitives. These are NOT proof that generic chat forms, credential isolation or multi-site orchestrators exist today.

WordPress Abilities API (6.9+) documentation: https://developer.wordpress.org/apis/abilities-api/ ; input/output schema and required permission callback: https://developer.wordpress.org/apis/abilities-api/php-reference/ ; Settings API option registration/sanitization: https://developer.wordpress.org/reference/functions/register_setting/. WordPress supports only a subset of JSON Schema syntax; domain schemas require an explicit compatible compiler before registering abilities.

Unresolved to verify through disposable prototypes: interactive form renderer capability and fallback within ChatGPT; secured short-lived secret ingress host and external Vault vs plugins that require WordPress DB plaintext; provider-native ACF/JetEngine/Elementor/Rank Math/WooCommerce/WPML save hooks, serialization and actual rollback; OAuth resource/step-up subject mapping; cross-site plugin schema mapping; workflow provider compatibility (Bit Flows) and owner rights; signed external Browser/Host keys; key rotation and privacy retention. A missing adapter is an explicit product limitation, not a mandate for arbitrary DB access.

Validation profiles: All Royal Egypt Staging for tours/media/SEO, ETG Staging for WPML/CPT filters/relations, and disposable clean WordPress PHP7.4/8.3 plus MariaDB/MySQL fault suites. Live Production not an implementation test bed.
