# ACI01 consolidated next integration — Native relations, dynamic recipe gaps, offline acceptance

**Delivery scope:** source-only read surfaces and acceptance wiring. Staging/Production execution remains separately governed. CI is not a release oracle.

## Reuse and source additions

1. `mad4b/aci01-native-relation-audit` is a new **read-only** WordPress Ability mounted on the existing MAD4B read adapter. It calls the existing `MAD4B_SCP_Translation_Bridge_Adapter::translation_get_post`, never native language setters/linkers. The actor must have `read_post` for source **and each translated post ID**, denying unknown group, duplicate post IDs across locales, wrong post type, missing expected locale, unreconciled provider status and changed generation/restore epoch between observations.
2. The returned post relationship is **observed**, never certified. Term namespaces, field translation policy, media relations, rendered hreflang and site-specific WPML mapper semantics remain `NEEDS_EVIDENCE`, independent of CPT taxonomy count.
3. `MAD4B_SCP_ACI01_Recipe_Gap::evaluate` consumes a pinned semantic profile and a bounded domain-recipe declaration + evidence receipts. Requirements are **data**, not hardcoded by post type or site. A mismatched profile/authority hash, duplicate requirement, cross-semantic receipts or arbitrary extra facts are denied. Matching receipt SHAs are still unverified observations, not rights authority. A missing reviewed recipe remains `NEEDS_EVIDENCE`; never replace it with a default tourism/article recipe.
4. Opportunity/Blueprint candidate includes `reviewed_domain_recipe` requirement until a separately governed manifest exists. It cannot advance to publishing.
5. The existing `tests/feature007-manual-preflight.py` and admitted CI workflow now execute/lint the full ACI01 PHP files and standalone negative fixtures at exact HEAD, **when those commands are run**. A configured job or fixture file by itself is `NOT_RUN`.

## Release boundaries

- **Never** infer translation identity from `wpml_object_id` fallback alone. No fabricated term-ID parity.
- **Never** infer commercial requirements from `post_type` spelling. A content recipe is a reviewed, environment-bound declaration.
- No new database table, wp_option writer, elevated OAuth scope, Shell/SSH, paid search API call, plugin installation, WordPress content mutation or Production operation is introduced.
- All unexecuted, external provider, Staging, browser and performance gates remain `OPEN` / `NOT_RUN` / `EXTERNAL_PENDING`; owner approval cannot be generated by the model.
- Work Map SHA must be recalculated from the latest actual changed path list; never rewrite concurrent contributors' files with stale blobs.
