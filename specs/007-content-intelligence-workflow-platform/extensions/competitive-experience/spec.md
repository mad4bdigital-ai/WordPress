# Specification — Competitive Experience and Governed Capability Breadth

Contract: `mad4b.competitive-experience-extension.v1`.

## Problem and intended behavior

The operator must be able to discover, configure and use admitted capabilities
without interpreting internal readiness structures or searching for hidden
credential fields. The earlier SerpApi setup gap and direct admin-slug 404s make
this an all-page journey requirement. Competitor breadth also exposes useful
Undo, consent, history, analytics, forms, commerce, builder and AI application
workflows whose parity must be measured by behavior and usability.

After each provider/build change, compatible reads remain usable and only the
affected capability is isolated. An operator sees what is usable, what needs
configuration, what needs external consent or host action, and what needs actual
behavioral certification. Every state has a next step and evidence provenance.
Initial Brand Strategy approval, Production authority, OAuth scope re-consent and
host sandbox installation retain their respective owner/external boundaries.

## Scope and user stories

1. As an administrator, I can reach every page/tab/control and configure an
   admitted provider/account/profile, including empty and denied states, with
   persisted readback and no implicit paid requests or secret disclosure.
2. As an operator, I can inspect a proposed change, approve its exact scope,
   verify the stored/emitted result and preview an eligible Undo with a clear
   expiry, current-state check and non-reversible effects.
3. As an owner, I can understand each agent/client's effective object-level
   permissions and consent, suspend/revoke access, and see attributable activity.
4. As a content/growth team, I can combine admitted analytics, search, keyword,
   backlink and competitor evidence with explicit site/property/window/language,
   provenance, cost and freshness rather than treating a score as write authority.
5. As a site operator, I can use admitted forms, commerce, builders, SEO, backup,
   cache, redirects and community workflows through native typed adapters, with
   privacy and high-risk effects classified independently.
6. As a content author, I can optionally use governed AI conversations, models,
   media, knowledge/PDF retrieval and AI forms while keeping generated/retrieved
   instructions untrusted and publication separately authorized.
7. As a maintainer, I can compare immutable package snapshots and task progress
   without treating advertised Pro features, tool counts or static code as proof.

## Requirement inventory

`capability-matrix.json` is the complete 59-row requirement inventory (40 competitor requirements plus 13 user-proposal Adaptive Operations requirements plus 6 architecture-derived resilience requirements). It binds
each CE001–CE053 requirement to a workstream, exact evidence IDs, existing MAD4B
source paths, implementation delta, five implementation/acceptance tasks,
acceptance conditions and denial cases. `traceability.md` exposes the same mapping.
Each task belongs to exactly one workstream. Dependencies must be acyclic.

Existing foundation means code that can support the requirement. It proves
neither absence nor full feature parity. No existing feature is reclassified as
missing solely from a competitor description. Acceptance assesses runtime and
operator behavior against the defined delta.

## Progress and evidence semantics

- Initial capability and workstream state is `OPEN`; all tasks are OPEN.
- Source states: `BUNDLED_STATIC`, `CLAIMED_UNVERIFIED`.
- Future implementation states must separate repository tests, disposable
  provider behavior, live provider/account certification and real browser use.
- A historical live count/version or claimed security feature is not current
  exact-build evidence. A file/class/tool name is not conformance.
- Archive maintenance, documentation and Spec CI cannot close implementation
  tasks or grant Production readiness. No task ratio is a readiness metric.

## Provider breadth

The named competitor integrations are conformance targets and examples for
generic adapter families, not core vendor switches or required site installs.
Track GA4, Search Console, Semrush, SE Ranking, Ahrefs, SerpApi/DataForSEO; CF7,
WPForms, Gravity/Fluent/JetFormBuilder; WooCommerce; Elementor, Divi, Kadence,
Gutenberg/FSE; Yoast/Rank Math/AIOSEO/SEOPress/Slim SEO/The SEO Framework; ACF,
WPML/generic languages, BuddyPress/Events Calendar; backup/cache/migration,
security/redirect providers; and optional AI/model/vector providers independently.

Current site applicability, installed artifact and entitlement are prerequisites
to observe, never proof of safe writes. Direct database access, generic shell,
arbitrary PHP/API execution, wildcard full access and automatic mounting are not
competitive feature goals.

## Release boundary

CE01 is an optional future backlog registered inside Feature 007. It is outside
the frozen release's 39 phases, 837 tasks and 34 workstreams. Its independent
ledger must not change current release closure, owner attestation, provider
certification, grants, candidate binding, Production authority or Breakglass.
Implementation slices require the same exact-head and real acceptance evidence
as existing governed capabilities.

## Adaptive Operations Fabric v2 extension

[adaptive-operations.md](adaptive-operations.md) and [its runtime contract](contracts/adaptive-operations-runtime.md) add 19 linked workstreams and 95 OPEN tasks. CE054–CE059 are architecture-derived in `architecture-expansion.md`. The loop uses observed facts, non-authorizing proposals, reviewed autonomy levels, exact read/canary evidence, signed registry packs, field ownership and real verification. No classifier, manifest or pack creates authority. Automation percentages remain aspirational until measured on an explicit eligible workload.

## Resilience evidence boundary

CE054–CE059 are architecture derivations from long-lived adaptive-operation failure modes. They justify backlog scope only; they are not runtime measurements, competitor evidence, certification, grants or authority.
