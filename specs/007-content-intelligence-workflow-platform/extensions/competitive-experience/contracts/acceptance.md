# Contract — Competitive Capability and Journey Acceptance

Contract: `mad4b.competitive-experience-acceptance.v1`.

## Evidence layers

| Layer | Proof required | Cannot substitute for |
| --- | --- | --- |
| Archive/static | Exact original archive/member/range hashes, truthful source class | Runtime availability or safe behavior |
| Repository | Exact-head executable tests and named denial fixtures for the implemented delta | External MCP, paid account, live canary or browser |
| Disposable provider | Real WordPress/provider artifact, isolated object, before/after native/read/rendered result and admitted rollback | Current live site/provider account |
| Live capability | Exact deployed source/build/site/subject/artifact/schema/transport, real admitted operation and signed receipt | Production permission or unrelated capability |
| Browser journey | Actual browser provider records reachable page/tab, accessible controls, configuration save/readback and denial/empty/error states | Synthetic HTML/status or disposable rendering |
| External MCP | Valid initialize and tools/list tied to the same actual client/session/resource/issuer/subject/build inventory | Server-local status or a fabricated snapshot |
| Performance | At least three comparable frontend samples plus the admitted workload's configured budgets | Invented universal thresholds or another release |

Every future completion records exact scope and layer. An implemented read does
not close a mutation task; structural compatibility does not close behavior;
history capture does not close Undo. Unknown or stale proof remains unverified.

## Required acceptance suites

1. All-page route, setup and typed-save/readback journeys for permitted and denied
   actors, empty providers/profiles, expired nonce/session, rejected OAuth scope,
   concurrent revision and Arabic/RTL keyboard/mobile behavior.
2. Identity/consent list/call/commit revalidation with revocation, demotion,
   wrong issuer/resource/server, stale generation, Origin and refresh replay.
3. Mutation/Undo readback under stale postconditions, single-use concurrency,
   partial provider success, crash/evidence failure and irreversible external effect.
4. Native provider matrix for applicable forms, commerce, builders, SEO, languages,
   fields, backup/cache/redirect/security and community operations, with field/PII,
   serialization, hook, editor-lock, financial and rollback-specific denial cases.
5. Analytics/model/media/RAG/provider egress and cost tests covering unknown cost,
   mixed currency/window/property, prompt injection, poisoned source, tenant leaks,
   malformed file, missing rights, external uncertainty and unsafe retries.
6. Capability-local update convergence, exact catalog/grants/Skills reconciliation,
   actual external handshake, browser paths and comparative performance evidence.

`capability-matrix.json` supplies the concrete per-requirement acceptance and
denial cases; every row must be represented in future executable suites. Full
parity is declared only for the accepted capability/version/site/operation scope.

## Spec integrity and progression

The initial contract is `SPEC_BACKLOG_ONLY`, with 145 OPEN tasks, 53 OPEN capability
rows and 29 OPEN workstreams. `validate.py` rejects checkbox-only completion,
invalid phase parity, source hash drift, missing artifacts, unsafe ZIP members,
unmapped/duplicate ownership, missing boundaries and release-scope widening.
`test_validation.py` tests meaningful negative cases for these rules.

Future implementation changes the extension state and evidence model in a reviewed
implementation PR; it must not loosen a validator just to label docs/static
observations DONE. Completion receipts identify executed fixtures, exact source/
artifact/site scope, real readback, drift/rollback proof and required external
evidence. Existing Feature 007 frozen release counts and live readiness remain
independent. No acceptance record grants Production, Breakglass or new authority.

Adaptive Operations acceptance additionally requires hostile discovery/annotations, policy proposal uncertainty, typed manifest binding, preauthorized shadow/canary, signed-pack lifecycle/anti-replay, three-way ownership, generation-fenced update/rollback, measured host/provider prerequisites and truthful workload-denominator fixtures. `adaptive-operations.json` does not certify an implemented autonomous runtime.
