# Contract — Competitive Experience Runtime and Adapter Boundaries

Contract: `mad4b.competitive-experience-runtime.v1`.
State: future implementation contract, non-authorizing.

## Capability descriptor and comparison model

Each semantic capability records stable identity, family, provider/artifact
identity, schema/contract fingerprint, site applicability, read/write risk,
object/field scope, reversibility/irreversible effects, certification requirements,
credential/consent prerequisites, egress/cost/privacy policy, operator routes and
evidence/receipt links. Candidate discovery is separate from reviewed risk policy.
New or unknown capabilities remain unclassified and fail closed.

Comparison records link requirement ID, competitor snapshot SHA, source range
hash, evidence class, MAD4B baseline source, implementation delta, task owner and
acceptance results. Competitor snapshot changes produce a semantic diff, not an
automatic provider install, code copy, authority expansion or compatibility claim.
Version drift is informational until contract/behavior evidence establishes a
capability-specific incompatibility. Unrelated compatible capabilities stay usable.

## Operator journeys

All registered pages/tabs/forms belong to the central route/operability inventory.
Every journey has canonical URL, allowed actor/capability, credential/account/
profile setup, typed save identity, nonce/revision fence, exact persisted readback,
empty/denied/error/stale state, and one precise next action. Legacy aliases retain
WordPress authentication/capability checks. Arabic/RTL, keyboard, mobile and
accessible labels are acceptance dimensions.

Configuration save is separate from explicit network testing and paid execution.
No GET rendering sends provider requests. Secrets remain encrypted behind opaque
handles and cannot appear in DOM, status, audit, diffs, logs or exported evidence.
Provider adapters supply fields and pinned endpoint contracts; arbitrary URLs are
not accepted. Google new-scope consent, host sandbox installation, first Brand
authority and Production grants remain explicit external/owner actions.

## Consent and NHI

UI projects existing enrolled subject/client/issuer/resource/server authority,
object capabilities, exact grants, risk and candidate generation. NHI/role views
cannot become a parallel permission system. Consent presets select bounded
reviewed scopes; no generic full-access preset, wildcard write or discovered-tool
auto-mount. Revocation, deletion/demotion, changed resource/session/schema and
grant generation are revalidated at list, call, provider entry and commit.

## Change history and reversal

History records redacted before/after typed values, affected object/field IDs,
actor/client, operation/approval/readback digests and outcome/uncertainty. History
is not rollback authority. Reverse eligibility requires a governed provider
contract, complete retained pre-state, current postcondition match, live subject
authority, expiry/retention, an exact reversal plan and a single-use claim.
Partial/unknown side effects reconcile before retry. Financial/refund/payment,
email/webhook, cache, external API and irreversible deletion effects are described
honestly; no universal Undo promise or fixed 72-hour policy is inherited from Royal.

## Native adapter families

Read and mutation certification are independent, capability-local and bound to
exact artifact/schema semantics. Native forms/SEO/builder/custom-field APIs own
serialization and hooks; generic metadata CRUD is not native parity. Builders
respect active editor locks and exact revisions, regenerate clone identities and
verify stored plus rendered structure. Multi-language taxonomy changes require
explicit source language, translation groups and parent mappings. A license notice
produces vendor/owner remediation, never automatic deactivation/reactivation.

Commerce splits catalog/stock/order/customer/fulfillment/payment/refund/webhook
effects. PII and financial operations require dedicated authority and real canary
evidence; irreversible effects never borrow a reversible catalog certification.
Backup/restore/migration respect protected recovery roots and restore epochs;
installer URLs and secrets are masked. Cache/redirect/security changes specify
blast radius and avoid origin bypass, loops, self-lockout or generic HTTP.

## Growth and AI

Analytics/search evidence preserves site/property/query/surface, market/language,
attribution/sampling/window, provider/currency/quota/cost and rights/freshness.
Mixed dimensions are not silently comparable. Signals produce proposals, never
direct mutations. Existing Search profiles, budgets, account authority, circuit
breakers, immutable observations and reconciliation-before-retry are reused.

Optional AI Workspace, model/media/audio/video, RAG/PDF/vector and AI forms use
approved provider contracts, per-user/tenant data access, source/asset rights,
cost reservations and explicit publication authority. Generated/retrieved text,
tool arguments and files are untrusted. Model fallback cannot silently alter data
residency, privacy, budget or authority. No arbitrary function/API/shell surface.

## Hard boundaries

`no_production_authority`, `no_breakglass_widening`, `no_generic_outbound_http`,
`no_direct_content_mutation_from_signal`, `no_vendor_or_business_hardcode`,
`no_documentation_only_completion`, `archive_reference_only_no_install_or_execute`,
`marketing_is_not_runtime_evidence`, `no_automatic_grants_or_tool_mounts`,
`capability_local_certification`, `history_is_not_rollback`,
`new_scopes_require_external_consent`, `no_generic_full_access_consent`.
