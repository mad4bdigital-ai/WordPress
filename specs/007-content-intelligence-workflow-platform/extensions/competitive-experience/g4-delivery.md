## Implemented repository behavior

Three private administrator abilities expose domain coverage inventory, exact
preflight proposals and independent observational readback. The shared planner
selects reviewed domain strategies, never vendor callbacks from user input.
Installed reviewed PHP provider objects own schemas, serialization facts,
permissions, inspection and comparators. Unknown providers, capabilities,
strategies and fields fail closed; a discovery row cannot register a provider.

Plans bind the current runtime generation, provider artifact/version/contract,
canonical read descriptor, exact target/input, native state hash, actor and a
five-minute lifetime. Inspection rechecks permissions, provider/descriptor/runtime
drift and target identity. Readback refetches the native observation and rechecks
the bindings after comparison. Caller-supplied provider facts are rejected.
Raw provider values and diagnostics are not returned in plan/evidence responses.

The native bridges use the existing canonical WordPress Ability, its permission
check and the governed child execution fence. Direct adapter callback execution,
generic executors, outbound HTTP, installations and database mutations are absent.
Missing certification, artifact binding, native APIs or active parent execution
frames deny inspection. The installed-plugin catalog reports only the declared
plugin-file observation scope; it cannot certify provider absence, theme coverage,
readiness, version compatibility or write authority.

Canonical material rejects objects, floats, hidden format controls, excessive
depth/nodes/bytes and malformed UTF-8. URL/path, field-effect and domain-specific
denial fixtures are repository evidence, not live provider certification.
