# Generic cost composition — reference calculation

The new MU plugin `mad4b-generic-cost-composition-v1.php` adds a read-only calculation to the existing Product Cost Review Ledger. It uses the same dynamic registry mappings, native package preflight and original company profit policy. No separate cost store or public retail price source is introduced.

- Billing-basis quantity rules, explicit party/service/room/vehicle/cabin/guide counts, positive bounded decimal costs, conservative line rounding to minor units.
- Required included groups can use all-required, cheapest comparable reference or priority/weight ordering; manual/conditional selection remains unresolved rather than guessed. Extras/upgrades and optional references are separately listed. Missing inputs, duplicates, mixed billing bases and incomplete candidate groups block group selection or a complete registry margin preview.
- Native lodging totals are already extended; never multiply these totals by party, room or night count again. Native guide reference is selected by explicit language and multiplied by guide count. Native and generic registry scopes remain separate until semantic stage coverage and deduplication are verified.
- Cross-currency calculation uses one fresh native public FX snapshot with source/timestamp/hash, not a commercial FX approval. Missing or stale FX leaves the line unconverted. The native global company margin/markup preview runs once per calculated subtotal, not per component. Partial scope is clearly identified.
- The ledger exposes calculation context, line table, partial totals, margin preview, outstanding blockers, and original evidence. No commercial amount, approval, supplier receipt, Rate or order is written. The native generator contract remains `mad4b.package-approved-price-composition.v1`; no fake approved-price adapter or signature is registered.
