# Dynamic cost alert lifecycle and native readiness integration

The MU plugin `mad4b-dynamic-cost-alerts-v1.php` contributes a source-scoped provider to the existing `mad4b_content_readiness_issues_v1` ledger and transition journal. No second issue store, scheduler, receipt authority or commercial writes. Authorized existing pricing actor only; product edit rights and suspension checks. Native CP4 and Rate Planner continue owning their own alerts.

- Dynamic mapped components: missing cost/currency/basis, conflicting selection/quantity policies, incomparable billing bases, incomplete candidate coverage. Real saved review context: missing quantities, FX, duplicate source, manual/conditional selection and other calculation blockers. Native package structural findings cover guide coverage and transport classifications/required route evidence, and unavailable commercial composition authority. Original stage/receipt alerts remain unchanged.
- Deterministic issue identity = site/product/context/component/reason. Recheck can resolve only the same explicitly covered context and group, with all previous source members still observed. Missing or removed source, partial scan, unexamined context or unverified authority never proves readiness. New contexts do not implicitly supersede old ones. No closure simply because a signer callback was registered.
- Existing Rate Planner completion performs a bounded census of native published packages and rotating dynamic mapped product types, plus bounded saved review contexts. Existing post/term/JetEngine relation and relevant policy events wake the native planner scheduler; daily watchdog retained. No new cron. Explicit authorized CLI `wp mad4b dynamic-cost-alerts --product=ID --user=ID` or bounded batch without product. Automatic scanning depends on active authorized native planner runs; mapped types over 20 per batch rotate, not full immediate census. Saved contexts are rechecked up to eight per product per batch. No persisted dynamic mappings currently exist. Scope-specific arithmetic is not inferred from fabricated quantities.
- The existing readiness UI and board links point cost-related findings to Product Cost Review Ledger. Ledger shows original and new findings, including component/source-field evidence. Board creation stays with native permission/workflow checks; silent cost task service; already linked tasks can close/reopen under original mutation authority. No new board tasks or email/BitFlows dispatch explicitly performed in this deployment.
- Central broad scan must never resolve scoped dynamic-cost issues. Source/Wayfa live monolithic classes patched individually (pre-existing code versions differ), with shared readiness lock also restored in older Wayfa full reconciler; no unrelated version downgrade. Git branch uses split reconciliation trait and class; equivalent narrow changes applied to those files, not wholesale replacement with live monolith. Live original CP4 and Rate Planner rows preserved.
