# Inquiry-first release — Fluent Forms / FluentCRM / FluentBoards / FluentSMTP

**Verification date:** 2026-10-29. **Target:** ETG WooCommerce Lab `local` isolated on VPS, database `etg_woocommerce_lab`. The feature is **request-only**, not a checkout or booking release. No Production mutation.

## Implemented source

`wp-content/plugins/commerce-composition/includes/InquiryPhaseOperations.php` is registered in the existing Commerce Composition boot file. It:
- Requires a **site-bound, admin-owned** option `commerce_inquiry_phase_config_v1` and explicitly selected Fluent Forms IDs, initially form **#6 only**.
- Permits automatic use of the **existing** idempotent workflow job `create_request_from_saved_submission` only when the original persisted Fluent Submission and server-owned Tour/Rate context pass `SubmissionProvenance` and `FluentSubmissionAdapter`, in `request_only` mode with checkout and cart authority false. The existing `AutomationEvents::onFluentSubmission` owns the queue; the new module does not create an alternate queue or duplicate submissions.
- Exposes a **management-authorized**, no-cache readiness REST route and an estimated current Rate-catalog price preview for **saved submissions only**. It makes clear that the price is not the immutable value shown on original submission, not a final Quote, that unit and taxes are not certified, and payment/booking is not enabled.
- Includes non-secret readiness flags for Fluent Forms' native Honeypot, time-limited token, Google reCAPTCHA v3, CRM native feed, FluentBoards and SMTP. It **does not** expose API keys.

## Current site-bound settings

Woo Lab form #6 inquiry intake config is enabled with an authorized admin actor, `crm_first` routing, native review and idempotent workflow. All other form IDs remain excluded from automatic intake by this option.

Fluent Forms' **native** global `_fluentform_global_form_settings.misc.honeypotStatus` and `tokenBasedProtectionStatus` are now both `yes`, for the 10 currently published forms. All other global settings were preserved. The plugin's server-side `fluentform/before_insert_submission` verification hook enforces these settings. In its conversational-form path, the plugin independently manages token eligibility to avoid stale cached conversational tokens; the Honeypot remains available. No third-party CAPTCHA code or fake Google keys were introduced.

**reCAPTCHA v3 is NOT configured** on the inspected Woo Lab and ETG Staging copies: stored site/secret keys and form `recaptcha` elements were absent in read-only inspections. An earlier historical configuration claimed by the owner has not been recovered. Native Honeypot and token **are not equivalent to Google v3**, and must never be reported as a v3 success.

## Exact executed evidence

On isolated Woo Lab, native anti-spam **27/27 PASS** before activation (form-enabled simulation, valid/expired/cross-form tokens and HTML render); after activation **24/24 PASS** with independent process readback. Additional direct server-side verification rejected each of four invalid attacks before insertion:
1. missing Honeypot input;
2. nonempty Honeypot input;
3. missing native protection token;
4. forged protection token.

Those direct rejection calls returned Fluent Forms native JSON error responses. No real form submission was generated by those tests.

Inquiry intake regression **24/24 PASS** with persisted source eligibility, no duplicate job enqueue, forbidden context, estimate preview, no payment authority, and transaction rollback. Independent database readback after tests: workflow jobs 12, request batches 9, Woo HPOS Orders 1, Fluent Forms submissions 28, FluentCRM contacts 2 and FluentBoards tasks 6 — none of these counts were changed by the test.

Evidence on VPS: `/opt/commerce-components/evidence/etg-inquiry-phase-20261029/`, especially `native-antispam-preflight.json`, `native-antispam-activation.json`, `antispam-audit.out`, `antispam-{honeypot_missing,honeypot_filled,token_missing,token_invalid}.out`, and `inquiry-after-readiness.json`.

## Still NOT certified / no false GO

- **FluentSMTP:** no outbound connection configured. No test email to a real recipient, no delivery proof.
- **FluentCRM:** the existing source registry and 9 historic request links verify, but no active native FluentCRM form feed was found for #6; test only proves existing workflow availability, **not** that every new customer is automatically created or linked.
- **FluentBoards:** component readiness and existing linked tasks confirmed; live new case → task delivery still requires an end-to-end isolated test with appropriate permission and lifecycle.
- **Estimated price:** current catalog preview exists, but front-end form rendering and immutable estimated-price snapshot at submission are **not** yet connected.
- **Google reCAPTCHA v3:** requires original verified site/secret keys (or a newly authorized integration) and subsequent server-side negative/positive tests across all published forms.
- **Direct checkout, Woo paid Orders and supplier bookings remain disabled** for this workflow.

## Rollback / safe configuration

Source rollback: revert the module require and bootstrap call in `composition.php` and remove only `InquiryPhaseOperations.php`. Global native spam protection can be reverted by restoring prior exact `misc` values of Honeypot and Token settings; do not delete other Fluent global settings. The inquiry option can be changed to `enabled=false` for this particular Woo Lab site without changing other tenants.
